1.1. Hệ thống có đúng ba business module:

1.2. Mỗi module là một solution folder trong ProjectMgmt.slnx, không phải facade
     project và không phải solution con. Bên trong mỗi solution folder có đúng ba
     class library thật:
     - <Module>.Domain

     - <Module>.Infrastructure

1.3. Cây trong Solution Explorer:

     folder sẽ chỉ xuất hiện local cho đến khi có source AI thật.

2. CHIỀU PHỤ THUỘC VÀ DI
======================================================================

     <Module>.Application    -> <Module>.Domain + ProjectMgmt.Contracts
     <Module>.Infrastructure -> <Module>.Application + <Module>.Domain
     ProjectMgmt.Solution    -> ba Application + ba Infrastructure + Foundation

Application không tham chiếu Infrastructure. Domain không phụ thuộc EF Core. Module
không gọi trực tiếp implementation nội bộ của module khác; giao tiếp liên module đi
qua contract công khai trong ProjectMgmt.Contracts hoặc do host điều phối.

Toàn bộ DI đặt trực tiếp tại ProjectMgmt.Solution/Program.cs. Hiện Program.cs đọc một
connection string dùng chung và đăng ký ba DbContext. Khi có repository/service:

     builder.Services.AddScoped<IIdentityRepository, IdentityRepository>();
     builder.Services.AddScoped<IIdentityService, IdentityService>();

Consumer chỉ inject interface qua constructor. DI container của ASP.NET Core sẽ dựng
object graph. Nhiều ProjectReference tại host là đúng vai trò composition root và
không gây hỏng nếu không có vòng tham chiếu hoặc package/framework xung đột.

6. CONNECTION STRING VÀ CẤU HÌNH
======================================================================

6.1. ProjectMgmt.Solution/appsettings.json chỉ lưu:
     - ConnectionStrings:ProjectMgmt = chuỗi rỗng;
     - Database:Provider = Pomelo.EntityFrameworkCore.MySql;
     - Database:ServerVersion = 8.0.46.

Không đặt mật khẩu trong Domain, Application, Infrastructure, migration hoặc file được
commit. Connection string local đã được lưu bằng .NET User Secrets bên ngoài repository.

6.2. Tạo/cập nhật secret local:

     dotnet user-secrets --project .\ProjectMgmt.Solution set `
       "ConnectionStrings:ProjectMgmt" `
       "Server=127.0.0.1;Port=3306;Database=projectmgmt;User=root;Password=<MẬT_KHẨU>;SslMode=None"

SslMode=None chỉ dùng cho MySQL local hiện tại. Production/IIS phải cấp secret riêng,
bật TLS phù hợp và ưu tiên SslMode=VerifyCA hoặc VerifyFull.

6.3. Biến môi trường dùng cho IIS, container và design-time factory:

     ConnectionStrings__ProjectMgmt=<connection string môi trường>
     Database__ServerVersion=8.0.46

ASP.NET Core chuyển dấu gạch dưới kép thành dấu hai chấm. Program.cs fail-fast nếu
thiếu connection string. Cả ba context dùng chung database vật lý nhưng có lịch sử:
     __EFMigrationsHistory_IdentityExperience
     __EFMigrationsHistory_Planning
     __EFMigrationsHistory_DeliveryIntelligence

8. WORKFLOW CODE-FIRST: CODE -> DATABASE
======================================================================

Trong PowerShell tại thư mục repository, đặt connection string cho phiên terminal:

     $env:ConnectionStrings__ProjectMgmt =
       "Server=127.0.0.1;Port=3306;Database=<DB_MỚI>;User=root;Password=<MẬT_KHẨU>;SslMode=None"

Database mới/rỗng phải cập nhật theo thứ tự để thỏa FK liên module:

     dotnet ef database update --project .\ProjectMgmt.Modules.IdentityExperience\Infrastructure --context IdentityExperienceDbContext
     dotnet ef database update --project .\ProjectMgmt.Modules.Planning\Infrastructure --context PlanningDbContext
     dotnet ef database update --project .\ProjectMgmt.Modules.DeliveryIntelligence\Infrastructure --context DeliveryIntelligenceDbContext

Sau khi sửa entity/configuration, tạo migration trong đúng module:

     dotnet ef migrations add <TenMigration> --project .\ProjectMgmt.Modules.<Module>\Infrastructure --context <Module>DbContext
     dotnet ef database update --project .\ProjectMgmt.Modules.<Module>\Infrastructure --context <Module>DbContext

Không tự động Database.Migrate() khi startup production. Nên sinh script để review và
triển khai có kiểm soát:

     dotnet ef migrations script --idempotent --project <InfrastructurePath> --context <Module>DbContext --output <file.sql>

======================================================================
9. WORKFLOW DB-FIRST: DATABASE -> CODE
======================================================================

Reverse engineering đã được chạy thử thành công với provider Pomelo trên MySQL local.
Luôn scaffold vào thư mục tạm để review, không ghi đè trực tiếp 59 entity/config hiện có:

     dotnet ef dbcontext scaffold `
       "Server=127.0.0.1;Port=3306;Database=projectmgmt;User=root;Password=<MẬT_KHẨU>;SslMode=None" `
       Pomelo.EntityFrameworkCore.MySql `
       --project .\ProjectMgmt.Modules.DeliveryIntelligence\Infrastructure `
       --output-dir <THƯ_MỤC_TẠM> `
       --context ProjectMgmtScaffoldDbContext `
       --no-onconfiguring

Lưu ý: reverse engineer có thể rút gọn bảng nối thuần thành quan hệ many-to-many, vì
vậy số class scaffold không nhất thiết bằng số bảng. So sánh và phân vùng lại theo ba
module trước khi chép code vào project thật.

10. DATABASE projectmgmt HIỆN HỮU VÀ BASELINE
======================================================================

Database projectmgmt đang có schema nhưng chưa có ba bảng __EFMigrationsHistory_*.
KHÔNG chạy các initial migration trực tiếp lên database này: EF sẽ cố tạo lại bảng.

Quy trình baseline an toàn:
     1. Backup database.
     2. So sánh schema hiện hữu với migration/script đã sinh.
     3. Chọn chiến lược baseline và ghi nhận sáu migration là đã áp dụng, hoặc tạo
        baseline migration riêng phù hợp quy trình vận hành.
     4. Thử trên bản clone/staging trước.
     5. Chỉ triển khai production sau khi review script và có phương án rollback.

Không tự ý chèn lịch sử migration vào database thật. Việc baseline phải là thao tác
vận hành có chủ đích và được phê duyệt.

11. KẾT QUẢ KIỂM CHỨNG
======================================================================

Đã apply đủ sáu migration lên database tạm độc lập, không sửa database projectmgmt.
Kết quả database sinh từ code:
     - 55 bảng nghiệp vụ;
     - 4 view;
     - 2 trigger;
     - 55 foreign key;
     - 33 CHECK constraint;
     - 173 index thực tế (167 khai báo + 6 index hỗ trợ FK do MySQL tạo);
     - 55/55 bảng có ROW_FORMAT=DYNAMIC;
     - 6 bản ghi lịch sử migration.

So sánh information_schema giữa database sinh từ migration và database nguồn:
     - Không lệch tên/thuộc tính cột, type, null, default, generated expression,
       charset, collation hoặc comment.
     - Không lệch index, uniqueness, index type, thứ tự cột hoặc index comment.
     - Không lệch FK/delete/update rule, CHECK, table engine/row format/comment.
     - Trigger và nội dung view được version hóa từ chính SQL nguồn.
     - dotnet build: 0 warning, 0 error tại lần kiểm chứng triển khai.

Database tạm chỉ dùng nghiệm thu và đã được xóa sau kiểm chứng. Dữ liệu thật trong
projectmgmt không bị migration thay đổi.
