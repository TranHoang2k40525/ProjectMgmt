Quyết định đã chốt

Cấu trúc này thay project façade bằng solution folder. Visual Studio sẽ hiển thị đúng ba project tầng dưới tên từng module mà không tạo thêm DLL trung gian.

1

Module là ranh giới nghiệp vụ

Chỉ có DeliveryIntelligence, IdentityExperience và Planning. Foundation/Runtime là hạ tầng hỗ trợ.

2

Ba project thật mỗi module

Domain, Application và Infrastructure đều có file .csproj riêng và tạo assembly riêng khi build.

3

Một solution chính

Không dựng solution con. Restore, build, test và publish từ ProjectMgmt.slnx để giữ dependency graph rõ ràng.

Vì sao không dùng class library cha? ProjectReference chỉ tạo dependency; nó không biến project được tham chiếu thành node con. Solution folder là cơ chế đúng để biểu diễn cây nhóm project trong Visual Studio.

Một template cho cả ba module

Mỗi folder chức năng chung có một file .cs rỗng để Git lưu cấu trúc. Không tạo folder riêng cho từng feature, nhờ đó namespace không bị kéo dài.

Domain

  • Entities/
  • IRepositories/
  • UseCases/

Thuần nghiệp vụ; không EF Core, ASP.NET, Application hay Infrastructure.

Application

  • IServices/
  • Services/
  • Dto/

Mỗi module chỉ có một bộ thư mục chung này. Feature mới được viết thành file, không lồng thêm cây tầng.

Infrastructure

  • <Module>DbContext.cs
  • Configurations/
  • Repositories/
  • BusinessLogicLayer/

EF Core + Pomelo, LINQ, repository và wrapper procedure/view/raw query.

Reference một chiều và DI tại Program.cs

Số lượng ProjectReference không phải rủi ro. Rủi ro là vòng tham chiếu hoặc cho một module chạm trực tiếp implementation nội bộ của module khác.

Applicationinterface, service, DTO
→
Domainentity, repository contract
←
Infrastructurerepository implementation, DbContext

Lưu ý chiều mũi tên: Infrastructure tham chiếu Application + Domain; Application chỉ tham chiếu Domain + Contracts. Application không được tham chiếu ngược Infrastructure.

ProjectĐược tham chiếuLý do
ApplicationDomain, ContractsDùng model/abstraction nội bộ và contract liên module.
InfrastructureApplication, DomainImplement abstraction và lưu dữ liệu cho module.
Solution3 Application, 3 Infrastructure, FoundationComposition root phải nhìn thấy interface lẫn implementation để đăng ký DI.
Module AContractsKhông tham chiếu trực tiếp implementation của Module B.

Luồng runtime: endpoint yêu cầu service → DI đọc đăng ký tại Program.cs → tạo service → inject repository interface → dùng implementation trong Infrastructure. Theo yêu cầu dự án, toàn bộ AddDbContext/AddScoped được đặt trực tiếp tại Program.cs.

MySQL và ownership dữ liệu

Schema chuẩn là projectmgmt_schema_mysql_optimized.sql, database projectmgmt. Ba DbContext có thể dùng chung một connection string nhưng mỗi context chỉ map bảng do module sở hữu.

ModuleNhóm dữ liệu dự kiến
IdentityExperienceUser/profile/login/OTP/token, role-permission, skill, organization, notification.
PlanningProject/version/workflow, board/sprint, issue/comment/attachment/label/acceptance criteria.
DeliveryIntelligenceActivity/history, workload/performance, AI model/prompt/dataset/training/evaluation.

Connection string chỉ đi qua ConnectionStrings:ProjectMgmt tại host. Local dùng User Secrets; IIS dùng ConnectionStrings__ProjectMgmt hoặc secret store. Không ghi mật khẩu vào class library hoặc commit vào appsettings.
