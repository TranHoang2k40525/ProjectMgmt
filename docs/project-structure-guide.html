Đã viết ở đâu?

Domain — Entity thuần

Mỗi bảng/view là một file trực tiếp tại:

ProjectMgmt.Modules.<Module>/
└─ Domain/Entities/<Entity>.cs

Entity chỉ có kiểu CLR và nullability, không phụ thuộc EF Core. Namespace: <Module>.Domain.Entities.

Infrastructure — Mapping

Mỗi entity có một mapping trực tiếp tại:

ProjectMgmt.Modules.<Module>/
└─ Infrastructure/Configurations/
   └─ <Entity>Configuration.cs

Tất cả dùng IEntityTypeConfiguration<T>. Namespace: <Module>.Infrastructure.Configurations.

DbContext và design-time

Infrastructure/
├─ <Module>DbContext.cs
└─ <Module>DbContextFactory.cs

Factory cho phép dotnet ef tạo/update migration mà không hard-code secret.

Migration

Infrastructure/Migrations/
├─ <timestamp>_<Migration>.cs
├─ <timestamp>_<Migration>.Designer.cs
└─ <Module>DbContextModelSnapshot.cs

Mỗi module có lịch sử migration riêng nhưng cùng kết nối một database vật lý.

Những phần của schema đã được map

  • Toàn bộ cột, kiểu dữ liệu, precision/length, nullability và tên cột.
  • CHAR(36) → Guid, text/JSON → string, TINYINT(1) → bool, số/date/datetime → CLR tương ứng.
  • Primary key, unique/composite/FULLTEXT index, thứ tự cột và comment của index.
  • Foreign key, tên constraint, delete/update behavior và 33 CHECK constraint.
  • Default SQL, ON UPDATE CURRENT_TIMESTAMP(6), generated/computed column.
  • Table/column comment, charset, collation, InnoDB và ROW_FORMAT=DYNAMIC.
  • 4 view là entity keyless; 2 trigger và nội dung view nằm trong migration.
  • Dữ liệu seed trong SQL cũng nằm trong migration: role, permission, role-permission, skill, priority, AI model, prompt và cleaning rule.

Một FK liên module AiEvaluationResult.ModelId → AiModel.Id được giữ trong migration cuối thay vì tạo ProjectReference chéo giữa hai Domain.

Kết nối MySQL và DI

Các package dùng Pomelo.EntityFrameworkCore.MySql 9.0.0 và EF Core 9.0.19. Local tool dotnet-ef 9.0.19 nằm trong .config/dotnet-tools.json. Không dùng đồng thời provider Oracle MySql.EntityFrameworkCore.

ProjectMgmt.Solution/appsettings.json chỉ giữ khóa rỗng và phiên bản server, không chứa user/password:

{
  "ConnectionStrings": { "ProjectMgmt": "" },
  "Database": {
    "Provider": "Pomelo.EntityFrameworkCore.MySql",
    "ServerVersion": "8.0.46"
  }
}

Local dùng User Secrets:

dotnet user-secrets --project .\ProjectMgmt.Solution set `
  "ConnectionStrings:ProjectMgmt" `
  "Server=127.0.0.1;Port=3306;Database=projectmgmt;User=root;Password=<MẬT_KHẨU>;SslMode=None"

IIS/container dùng ConnectionStrings__ProjectMgmt. SslMode=None chỉ dành cho máy local; production nên dùng chứng thư và VerifyCA/VerifyFull.

Ba context được đăng ký trực tiếp trong ProjectMgmt.Solution/Program.cs, đúng yêu cầu composition root:

builder.Services.AddDbContext<IdentityExperienceDbContext>(...);
builder.Services.AddDbContext<PlanningDbContext>(...);
builder.Services.AddDbContext<DeliveryIntelligenceDbContext>(...);

Mỗi context có migration history riêng: __EFMigrationsHistory_IdentityExperience, __EFMigrationsHistory_Planning, __EFMigrationsHistory_DeliveryIntelligence.

Hai chiều database ↔ code

Code-first: code → database

Đặt ConnectionStrings__ProjectMgmt cho terminal, sau đó chạy đúng thứ tự Identity → Planning → Delivery:

dotnet ef database update --project .\ProjectMgmt.Modules.IdentityExperience\Infrastructure --context IdentityExperienceDbContext
dotnet ef database update --project .\ProjectMgmt.Modules.Planning\Infrastructure --context PlanningDbContext
dotnet ef database update --project .\ProjectMgmt.Modules.DeliveryIntelligence\Infrastructure --context DeliveryIntelligenceDbContext

Khi đổi model: dotnet ef migrations add <Tên> --project <InfrastructurePath> --context <Module>DbContext.

DB-first: database → code

Scaffold đã được thử thành công với Pomelo. Luôn sinh vào thư mục tạm để review:

dotnet ef dbcontext scaffold `
  "<CONNECTION_STRING>" `
  Pomelo.EntityFrameworkCore.MySql `
  --project .\ProjectMgmt.Modules.DeliveryIntelligence\Infrastructure `
  --output-dir <THƯ_MỤC_TẠM> `
  --context ProjectMgmtScaffoldDbContext `
  --no-onconfiguring

Scaffold có thể biến bảng nối thuần thành many-to-many; phải phân lại entity về đúng module trước khi dùng.

Cảnh báo baseline: database projectmgmt đang tồn tại nhưng chưa có ba bảng lịch sử migration. Không chạy initial migration trực tiếp vì EF sẽ cố tạo lại bảng. Hãy backup, so sánh schema, baseline trên clone/staging rồi mới triển khai.
