# Definition of Ready

A work item may enter active development when:

- Objective and user/business value are clear.
- Description identifies backend, frontend, API, data, dependency, and test impact—or explicitly says not applicable.
- Acceptance criteria are concrete and testable.
- Provider/consumer Contract and data ownership are identified.
- Required predecessor work is done in an earlier sprint.
- No dependency on a later feature exists without an agreed Contract and fake.
- UX/API examples and failure behavior are clear enough to implement.
- Security/privacy/secret and migration implications were considered.
- Test data/environment needs are available.
- Owner, reviewer, module/component, priority, and estimate are assigned.
