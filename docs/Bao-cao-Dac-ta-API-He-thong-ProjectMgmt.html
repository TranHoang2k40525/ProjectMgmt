1. Quy Tắc Chuẩn Tắc & Thiết Kế API Toàn Hệ Thống

Base URL: https://api.projectmgmt.huce.edu.vn/api/v1

Xác thực (Auth Header): Authorization: Bearer

1.1 Quy tắc đặt tên (Naming Conventions)

Đối tượngQuy tắc đặt tênVí dụ cụ thể
URL Endpoint kebab-case danh từ số nhiều /api/v1/work-items, /api/v1/sprint-members
Query Parameter camelCase pageSize=20&searchQuery=CRM
JSON Field Name (Req/Res) camelCase đồng nhất toàn bộ 3 module issueKey, storyPoints, createdById
Database Mapping snake_case (MySQL) / PascalCase (C# EF Core) issue_key -> issueKey
Datetime ISO 8601 UTC string 2026-09-22T19:15:00.000Z
ID Format UUID / GUID v4 string 01a09072-8caa-7743-8a5f-be64f3d5c3b8

1.2 Cấu trúc Phản Hồi Chuẩn (Standard Response Wrapper)

Giúp Frontend xử lý đồng nhất 100% các request, tránh lãng phí gọi nhiều API nhờ gộp data đơn lẻ hoặc danh sách phân trang trong 1 HTTP response duy nhất.

Single Object Response: 
{
  "success": true,
  "code": "200",
  "message": "Thao tác thành công",
  "data": { ... }
}
Paged List Response: 
{
  "success": true,
  "code": "200",
  "message": "Thao tác thành công",
  "data": {
    "items": [ ... ],
    "totalCount": 120,
    "page": 1,
    "pageSize": 20,
    "totalPages": 6
  }
}

Module 1: IdentityExperience (Danh Tính, Quyền & Trải Nghiệm AI 1)

Phụ trách Module: Trần Văn Hoàng (A)

Bảng DB sở hữu: 16 bảng (User, UserProfile, ExternalLogin, OtpCode, RefreshToken, Role, Permission, RolePermission, UserRole, SkillCatalog, UserSkill, AiModel, AiPromptTemplate, AiGenerationLog, AiSuggestedTask, Notification)

Quản lý toàn bộ danh tính người dùng, xác thực JWT & OTP, phân quyền RBAC theo scope, quản lý danh mục kỹ năng, hệ thống thông báo realtime/inbox và động cơ phân rã User Story AI 1.

POST /api/v1/auth/register
Đăng ký tài khoản mới
Tạo tài khoản người dùng mới trong hệ thống, kích hoạt mã gửi OTP qua email.

{
  "email": "string (email format, unique, required)",
  "password": "string (min 8 chars, 1 upper, 1 special, required)",
  "fullName": "string (max 100 chars, required)",
  "phoneNumber": "string (optional)"
}
Dữ liệu trả về cho FE (Response Data): 
{
  "userId": "string (UUID)",
  "email": "string",
  "fullName": "string",
  "status": "string (PendingVerification)",

}
Bảng MySQL tương ứng: Bảng `User`, `UserProfile`, `OtpCode`

Tạo Issue mới. Mã Issue (issueKey) được cấp nguyên tử từ Planning (`IIssueNumberGenerator`). Kiểm tra workflow status ban đầu.
Dữ liệu truyền từ FE (Request Body): 
{
  "projectKey": "string (required)",
  "title": "string (max 255 chars, required)",
  "description": "string",
  "issueType": "string (Epic | Story | Task | Bug | Sub-task, required)",
  "priority": "string (Low | Medium | High | Highest, required)",
  "sprintId": "string (UUID, optional)",
  "parentIssueId": "string (UUID, optional - bắt buộc nếu là Sub-task)",
  "assigneeId": "string (UUID, optional)",
  "storyPoints": "number (optional)",
  "estimatedHours": "number (optional)",
  "acceptanceCriteria": [
    "array of string (optional)"
  ]
}
Dữ liệu trả về cho FE (Response Data): 
{
  "issueId": "string (UUID)",
  "issueKey": "string (e.g. CRM-106)",
  "title": "string",
  "statusName": "string (To Do)",
  "createdAt": "string (ISO 8601)"
}
Bảng MySQL tương ứng: Bảng `Issue`, `AcceptanceCriteria`, `ActivityLog`

PUT /api/v1/issues/{issueKey}/status
Cập nhật chuyển trạng thái (Workflow Transition)
Chuyển trạng thái Issue. Kiểm tra tính hợp lệ qua `IWorkflowValidationService` của Planning. Lưu vết IssueStatusHistory.
Dữ liệu truyền từ FE (Request Body): 
{
  "targetStatusId": "string (UUID, required)",
  "comment": "string (optional)"
}
Dữ liệu trả về cho FE (Response Data): 
{
  "issueKey": "string",
  "previousStatusId": "string (UUID)",
  "newStatusId": "string (UUID)",
  "statusName": "string",
  "updatedAt": "string (ISO 8601)"
}
Bảng MySQL tương ứng: Bảng `Issue`, `IssueStatusHistory`, `ActivityLog`
POST /api/v1/issues/{issueKey}/comments
Thêm bình luận vào công việc
Tạo bình luận mới cho Issue. Tự động quét các lượt `@mention` để tạo thông báo qua `INotificationSender` của IdentityExperience.
Dữ liệu truyền từ FE (Request Body): 
{
  "content": "string (required)",
  "mentionedUserIds": [
    "array of UUID (optional)"
  ]
}
Dữ liệu trả về cho FE (Response Data): 
{
  "commentId": "string (UUID)",
  "issueKey": "string",
  "authorName": "string",
  "authorAvatarUrl": "string",
  "content": "string",
  "createdAt": "string (ISO 8601)"
}
Bảng MySQL tương ứng: Bảng `Comment`, `ActivityLog`
POST /api/v1/issues/{issueKey}/attachments
Tải lên tệp đính kèm công việc
Tải lên tệp đính kèm. Kiểm tra an toàn loại tệp, dung lượng và quyền hạn người dùng trước khi lưu trữ.
Dữ liệu truyền từ FE (Request Body): 
Multipart Form Data (file: Binary, required)
Dữ liệu trả về cho FE (Response Data): 
{
  "attachmentId": "string (UUID)",
  "fileName": "string",
  "fileUrl": "string",
  "fileSize": "number (bytes)",
  "uploadedAt": "string (ISO 8601)"
}
Bảng MySQL tương ứng: Bảng `Attachment`, `ActivityLog`
